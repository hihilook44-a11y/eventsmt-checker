# Read-only source check

The workflow runs every two hours at minute 17 (GitHub may delay or skip scheduled runs). It checks at most three pages of the public source account. A successful first run creates a baseline; later runs count unseen video posts newer than the last successful scan. Pagination duplicates and repeats are tracked across runs using SHA-256 digests of public post IDs in `state/seen_post_ids.json`; the workflow commits that state with its repository token. The raw IDs, post text, URLs and media are not written to the ledger or printed in logs. The repository is public, so the digests and scan times are public too; a digest is pseudonymous, not a secret, and does not conceal which public posts are being monitored from someone able to query the source.

State advances only after a complete successful scan. The source request retries once after a transient network, server, or truncated-JSON error; final failures report only a safe error category (not URLs or response bodies). If the source or state is incomplete/corrupt, the run fails closed and does not advance the ledger. The ledger is capped at 5,000 IDs; the scan checks at most three pages, so it may miss posts if the source is more active than that coverage. A successful schedule only counts new video posts; it does not identify or deliver candidate media for publication, assess audio, edit videos, make thumbnails, or publish. It is deliberately not connected to Wabi's private queue or WoopSocial credentials.

No clips, account credentials or publishing tokens belong in this public repository. Do not treat a positive video count as evidence that a clip is song-free or authorized for publishing.

## WoopSocial REST scaffold (not connected to the workflow)

`woopsocial_scaffold.py` builds authenticated WoopSocial REST request objects for the documented `/v1/media` and `/v1/posts` endpoints. It reads `WOOPSOCIAL_API_KEY` only from the process environment (for a future GitHub Actions run, that should be a repository Actions secret). It does not contain an HTTP sender, and request representations suppress header values and body contents. Upload and YouTube-post payloads are covered only by fake-transport tests; the YouTube request is hard-coded to `DRAFT`, never `PUBLISH_NOW`.

`publication_state.py` is an isolated future-state helper: only SHA-256 digests are written. A pending or outcome-unknown item cannot be retried automatically; only a confirmed provider success is recorded as published. Tests use temporary directories and fake responses, not the connected account. Neither module is called by `check.py` or `.github/workflows/check.yml`.

The scheduled workflow remains a public aggregate source checker, not a publisher. Do not wire posting into it until private state and credentials can be handled safely and an audio gate reliably proves a clip contains no songs. The existing Wabi WoopSocial connection is not a GitHub Actions credential. If a future integration is enabled, create a separate WoopSocial API key in the dashboard and add it directly as the repository Actions secret `WOOPSOCIAL_API_KEY`; never paste it into chat, code, logs, or repository files. No real media was uploaded or post created by these tests.
