# Read-only source check

The workflow runs every two hours at minute 17 (GitHub may delay or skip scheduled runs). It checks at most three pages of the public source account. A successful first run creates a baseline; later runs count unseen video posts newer than the last successful scan. Pagination duplicates and repeats are tracked across runs using SHA-256 digests of public post IDs in `state/seen_post_ids.json`; the workflow commits that state with its repository token. The raw IDs, post text, URLs and media are not written to the ledger or printed in logs. The repository is public, so the digests and scan times are public too; a digest is pseudonymous, not a secret, and does not conceal which public posts are being monitored from someone able to query the source.

State advances only after a complete successful scan. If the source or state is incomplete/corrupt, the run fails closed and does not advance the ledger. The ledger is capped at 5,000 IDs; the scan checks at most three pages, so it may miss posts if the source is more active than that coverage. A successful schedule only counts new video posts; it does not identify or deliver candidate media for publication, assess audio, edit videos, make thumbnails, or publish. It is deliberately not connected to Wabi's private queue or WoopSocial credentials.

No clips, account credentials or publishing tokens belong in this public repository. Do not treat a positive video count as evidence that a clip is song-free or authorized for publishing.
